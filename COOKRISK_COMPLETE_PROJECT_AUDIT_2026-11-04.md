## A. Executive summary

The repository contains substantial working software, data releases, schemas, tests, and provenance artifacts across Stages A–D. That does not amount to project completion: Stage A's historical benchmark discrepancy and inference gates remain open; Stage B retains scientific limitations and pending identity decisions; Stage C has incomplete/blocked integration and validation, with zero accepted end-to-end cooked-concentration results in the last documented Phase 2 audit; and Stage D still needs qualified human reviews, formal schema validation, external identity/checkpoint integrations, and independent validation.

## D. Cross-project integration

- **Data and interface dependencies:** Stage C consumes Stage B identities/evidence and Stage A retention inputs; Stage D binds exact Stage B evidence IDs to Stage C Phase 3 estimate IDs and release hashes. Contracts are designed to fail closed on mismatched IDs, hashes, units or contexts.
- **Provenance:** Stage B releases retain source audits and warnings; Stage C has ingestion/source-pair records and manifests; Stage D queue/registry records are source-hash-pinned. These do not establish independent re-review of every source.
- **Reproducibility:** Stage A's current pipeline is repeatable under its pinned macOS environment, but historical run discrepancy remains unexplained. Stage B/C/D releases have manifests and historical validation; current audit did not rerun them or validate clean-copy builds.
- **Schemas:** JSON syntax parsing has been performed for Stage D schemas; formal Draft 2020-12 validation is unavailable because the approved `jsonschema` pin/source is missing. Parsing is not schema validation.
- **Application:** Stage C is a local research prototype; its recorded health is degraded when Phase 4 context is unavailable. Stage D has workflow/report foundations, not a verified production application.
- **Release integrity:** Frozen releases are preserved. Stage B exact-vs-canonical hash policy wording is inconsistent. Stage C notes describe a Phase1B embedded dependency byte-integrity issue in a Windows working copy. Stage D integrity gates block Phase 4 dependent records and unanchored local histories remain vulnerable to full-history replacement.
- **Deployment:** Not established for scientific inference, review authorization or production use. No clinical/patient-specific risk capability is supported by this audit.

## E. Scientific validity assessment

Engineering implementation, computational repeatability, source-level evidence, independent scientific validation and human approval are distinct. A passing unit/synthetic test establishes only the tested software contract. It does not establish that all scientific measurements are correctly interpreted, food and compound identities are equivalent, a cooking conversion is valid, exposure is clinically comparable, or an interaction is approved.

The repository deliberately retains unresolved states. In particular, Stage C's last documented Phase 2 analysis supports **zero accepted cooked-concentration estimates**. Raw reference concentrations, measured cooking observations, model predictions, and unsupported estimates must remain separate. Stage D's 317 evidence records and 25 mechanism candidates remain pending qualified review. Stage A OOF predictions remain validation outputs, not inference for new records.
